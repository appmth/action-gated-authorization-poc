# Judgment UI（Next.js）実装計画（PoC / AGA）

## 前提

- **Frontend**: Next.js（App Router）
- **Backend**:
  - service-a = Agent + PEP（Cloud Run）
  - service-b = PDP（OPA / Cloud Run）
  - service-c = Tool（Cloud Run）
- **画面の目的**: 「AIが何をしようとして、なぜ止めた/なぜ実行したか」を request_id で説明可能にする

## ゴール定義（PoCで証明する3点）

1. **Contextで Allow/Deny が変わる**
2. **PEP が"実行前に必ず"止める（Denyは副作用ゼロ）**
3. **判断理由（reason）がログとUIに残り説明できる**

## 画面スコープ（3画面・最小）

- **[MVP] Dashboard**（一覧）
- **[MVP] Judgment Detail**（詳細：Plan / Decision / Enforcement / Trace）
- **[Nice-to-have] Policy Viewer**（読み取り専用）

※ PoCでは **Detail を主役**にする（審査員が見る場所）

## UI要件（MVP）

### 1) Dashboard（一覧）

**表示項目**:
- `request_id`（クリックで詳細へ）
- `action`
- `result`（ALLOW / DENY）
- `reason_short`（1行）
- `timestamp`

**機能**:
- Filter（最低限でOK）
  - action（固定でも可）
  - result（ALLOW/DENY）
  - time range（Last 24h だけでも可）

### 2) Judgment Detail（最重要）

**表示ブロック（順番固定）**:

1. **Overview**: request_id / action / result / timestamp
2. **Plan（Agent Proposal）**: `{ action, context }` のJSON（コピーボタン）
3. **Policy Decision（PDP）**: allow/deny + reason + policy_version + rule_id
4. **Enforcement（PEP）**: PDP consulted before exec / tool called? / side effects none?
5. **Audit Trace（タイムライン）**: Agent→PEP→PDP→Tool（Called/Not called）

**「刺さる見せ方」**:
- **DENY時**: 赤で "Tool NOT CALLED / Side effects: NONE" を強調（文言だけでOK）
- **ALLOW時**: Tool結果（ダミーでOK）を表示し、同じく trace に出す

### 3) Policy Viewer（Nice-to-have）

- Regoを読み取り専用で表示
- policy_version を併記

※ 編集UIは作らない（PoCの論点がズレる）

## 実装方式（最速）

### 方針: UIのために "Judgment Read API" を1本だけ作る

**service-a に以下を追加（最小）**:
- `GET /judgments`（一覧：最新20件）
- `GET /judgments/{request_id}`（詳細）

**保存先（PoC優先度順）**:

1. **インメモリ（開発用）** → すぐUIが作れる
2. **Firestore（推奨 / PoC本番用）** → デモ安定、一覧が壊れない
3. Cloud Logging のみ → UIから読むのが面倒なので避ける

※ すでに request_id があるので Firestore は素直に効く

## 現在の実装状況との統合

### 既存のエンドポイント

現在 service-a には以下のエンドポイントがあります：

- `POST /v1/agent/plan-and-act`: Plan生成 + PDP判定 + Tool実行
- `POST /v1/actions/get_resident_info`: 個別Action実行（レガシー）

### 必要な追加実装

#### 1. Judgment データモデル

```python
# service-a/models.py (新規)
from pydantic import BaseModel
from datetime import datetime

class JudgmentRecord(BaseModel):
    request_id: str
    created_at: datetime
    action: str
    context: dict
    plan_raw: str | None
    decision: dict
    pep_enforcement: dict
    tool_result: dict | None
    trace: list[dict]
    result: str  # "ALLOW" or "DENY"
    reason_short: str
```

#### 2. Firestore 保存ロジック

`/v1/agent/plan-and-act` エンドポイント内で、レスポンスを返す前に Firestore に保存：

```python
# service-a/main.py に追加
from google.cloud import firestore

db = firestore.Client()

async def save_judgment(judgment: JudgmentRecord):
    """Judgment を Firestore に保存"""
    doc_ref = db.collection('judgments').document(judgment.request_id)
    doc_ref.set(judgment.dict())
```

#### 3. 読み取り API

```python
@app.get("/judgments")
async def list_judgments(limit: int = 20):
    """最新の Judgment を取得"""
    docs = db.collection('judgments')\
        .order_by('created_at', direction=firestore.Query.DESCENDING)\
        .limit(limit)\
        .stream()

    return [doc.to_dict() for doc in docs]

@app.get("/judgments/{request_id}")
async def get_judgment(request_id: str):
    """特定の Judgment を取得"""
    doc = db.collection('judgments').document(request_id).get()
    if not doc.exists:
        raise HTTPException(status_code=404, detail="Judgment not found")
    return doc.to_dict()
```

### 実装優先度

1. **Phase 0-1**: インメモリ実装（`list[JudgmentRecord]` をグローバル変数で保持）
2. **Phase 2**: Firestore 移行
3. **Phase 3**: UI完成
