# AGA Hackathon 実行計画（2/15 提出）

## 前提
- テーマ：Action-Gated Authorization（AGA）
- 形態：個人 or 少人数
- 期間：約1か月
- 勝ち筋：課題新規性 × 実行前に止められるPoC × 説明可能性のデモ

---

## 全体マイルストーン
- 2/15：提出完了（GitHub / デプロイURL / Zenn記事 / デモ動画）
- 原則：毎週「審査員に見せられるデモ」が前進していること

---

## Week 0（今〜3日）
### フェーズ：計画・スコープ確定

**目的**
- 1ヶ月で確実に成立するスコープに絞る
- やらないことを明示する

**作業**
- AGA PoCの証明対象を3点に限定
- MVP / Nice-to-have / やらないことの整理
  - MVP = Minimum Viable Product（最小限成立するプロダクト）
  - Nice-to-have = あったら嬉しいが、なくても価値は壊れないもの
- 審査基準（新規性・有効性・実装）との対応付け
- デモ動画（3分）のラフ構成作成

**成果物**
- スコープ定義メモ
- 箱レベルのアーキテクチャ概要
- デモ動画の構成メモ

**デモ到達点**
- まだ動かなくてよい
- 何を見せるかを言語で説明できる状態

---

## Week 1
### フェーズ：骨組み実装（まず動かす）

**目的**
- Agent → Action → 認可ゲート、の流れを成立させる

**作業**
- Google Cloud 実行基盤準備（Cloud Run 等）
- Gemini API / Vertex AI で Action 候補生成
- PEP（仮実装）で Allow / Deny を返す
- 最小UI（ボタン＋ログ）

**成果物**
- 公開GitHubリポジトリ
- Cloud上で動くデモURL

**デモ到達点**
- AgentがActionを提案する
- 実行前にPEPで止められる
- 実行前ゲートの存在が視覚的に分かる

---

## Week 2
### フェーズ：AGAの核心（理由付き判断）

**目的**
- なぜ止めたか／許したかを説明できる状態にする

**作業**
- PDP導入（ルールベース or ポリシー評価）
- Context（目的・時間帯・PII有無など）を明示的に受け渡し
- 判定理由をレスポンスとして返却
- 監査ログ保存（Action / Context / 判定理由）

**成果物**
- PDP / PEP が分離された構造
- 理由が見えるログ or UI

**デモ到達点**
- 同じActionでも文脈で許可／拒否が変わる
- 拒否理由を人間に説明できる

---

## Week 3
### フェーズ：完成度・拡張性・見せ方

**目的**
- 実験ではなく「使えそう」に見せる

**作業**
- ポリシー変更で挙動が変わるデモ
- UI整理（Action一覧／判定理由／ログ）
- エラーハンドリング・暴発防止
- デモ動画本番撮影（3分）

**成果物**
- 安定したデプロイ環境
- デモ動画（YouTube限定公開）

**デモ到達点**
- ポリシー変更 → 即挙動反映
- 実務での利用イメージが湧く

## PoCで必ず証明すること
- Agentは自由に考える
- 実行は必ず認可ゲートを通過する
- 不適切なActionは実行前に止まる
- 判断理由が説明可能な形で残る
